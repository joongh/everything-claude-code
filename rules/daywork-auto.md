# Daywork 자동 기록

대화 중 특정 Dooray 태스크와 관련된 작업을 하고 있다는 게 **명확하게** 판단되면, 해당 태스크를 daywork(업무 일지)에 자동으로 기록한다. 사용자에게 별도 확인은 받지 않고, 기록 후 결과만 알린다.

## 발동 조건 (모두 충족해야 함)

다음 신호가 명확할 때만 자동 기록한다. 애매하면 기록하지 않는다.

1. **태스크 식별이 명확** — 다음 중 하나로 특정 Dooray 태스크가 확인됨:
   - 사용자가 Dooray 태스크 URL 또는 번호(`tc-xxx/숫자`)를 공유함
   - 브랜치 이름이 `tc-xxx/숫자` 형식이라 Dooray 업무 브랜치로 판별됨 (`git-workflow.md` 참고)
   - 사용자가 명시적으로 "이 태스크에 대해 작업 중"이라고 언급함
   - 대화 흐름에서 이미 특정 태스크 본문을 조회하여 그 내용을 바탕으로 작업이 진행 중임
2. **실제 작업이 진행됨** — 단순 조회/질문이 아니라 코드 수정, 분석, 문서 작성, 댓글 작성 등 그 태스크와 직접 연결된 활동이 한 가지 이상 발생함
3. **중복 아님** — 오늘 날짜 섹션의 daywork에 동일한 태스크 URL이 아직 없음
   - **판정 범위는 오늘 날짜 섹션뿐이다.** daywork는 그날의 업무 기록이므로 **어제 이전에 같은 태스크가 기록돼 있어도 오늘 다시 작업했으면 오늘 섹션에 또 기록한다.** 여러 날에 걸치는 태스크는 날짜마다 반복 등장하는 게 정상이다

위 셋 중 하나라도 충족하지 않으면 자동 기록하지 않는다.

## 자동 기록 대상이 **아닌** 경우

- 태스크가 두 개 이상 후보 중에서 어느 것인지 불분명함
- 사용자가 "이 태스크 잠깐 봐줘" 정도로 조회만 하고 끝남
- 회의/연차/면담 등 자유 텍스트 성격의 기록은 사용자 명시적 요청이 있을 때만 기록 (자동 기록 X)
- 브랜치 이름이 `tc-`로 시작하지 않거나 Dooray 업무가 아닌 경우

## 동작 방식

발동 조건이 충족되면:

1. 별도의 사용자 확인 없이 `daywork` 스킬을 사용하여 기록한다 (카테고리 분류·중복 확인 등 절차는 스킬 정의를 따른다)
2. 기록 후 사용자에게 짧게 알린다. 예:
   - `daywork 기록함: {카테고리} > {태스크 제목}`
   - 이미 오늘 기록되어 있어 스킵한 경우: `daywork에 이미 오늘 기록되어 있어 스킵함`
3. 카테고리 분류가 불확실해서 daywork 스킬이 질문을 던지는 단계에 도달하면, 그때는 스킬 정의대로 사용자에게 물어본다 (자동 기록 정책이 카테고리 분류 모호함까지 자동 결정하지는 않음)

## 주의

- 이 규칙은 **자동 기록**만을 다룬다. 사용자가 명시적으로 "daywork에 기록해줘"라고 요청한 경우는 기존 `daywork` 스킬 흐름을 그대로 따른다
- 한 대화 안에서 이미 자동 기록을 마친 태스크는 **같은 날 안에서는** 다시 시도하지 않는다 (중복 알림 방지). 단 세션이 날짜를 넘겨 이어지는 경우(장시간 대화)는 예외로, **날이 바뀌면 그날 작업한 태스크를 새 날짜 섹션에 다시 기록한다** — 세션 단위가 아니라 날짜 단위로 판단한다
- 기록 실패 시 즉시 사용자에게 실패 사실과 에러를 알린다 (조용히 넘어가지 않음)
