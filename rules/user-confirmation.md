# 사용자 확인 요청

## AskUserQuestion 사용 규칙

사용자에게 확인이나 선택을 요청할 때는 텍스트로 "진행할까요?" 등을 출력하지 말고, 반드시 `AskUserQuestion` 도구를 사용한다.

### 적용 대상

- yes/no 확인 질문 (예: "진행할까요?", "삭제할까요?", "커밋할까요?")
- 여러 옵션 중 선택 (예: 방법 A vs B, 파일 선택)
- 사용자 입력이 필요한 간단한 질문

### 사용 방법

1. **yes/no 질문**: 선택지를 명확히 제공하되, 자유 입력도 가능하게 한다
2. **다중 선택**: 번호나 키워드로 선택할 수 있는 옵션 목록 제공
3. **자유 입력**: 사용자가 선택지 외의 답변도 입력할 수 있도록 허용

### 수정 확인은 diff 본문 출력 + 턴 종료 (중요)

파일·Dooray 태스크·위키·댓글 등 **수정 내용을 확인받을 때는 이 절이 위 AskUserQuestion 규칙보다 우선한다.**

1. diff 원문을 답변 본문에 ```` ```diff ```` 코드 블록으로 출력한다
2. `AskUserQuestion` 을 띄우지 않고 **그 턴을 끝낸다.** 마지막 줄은 "반영할까?" 같은 한 줄 질문
3. 사용자가 채팅으로 답하면("반영", "수정: …") 그때 진행한다

이유:
- Bash 도구 출력에만 있는 diff는 사용자에게 안 보인다
- 본문에 diff를 쓰고 같은 메시지에서 질문 창을 띄우면 질문 창에 가려져 안 보인다
- 질문 창 `preview` 에 넣으면 보이긴 하지만 길면 읽기 힘들다

diff가 길면 바뀌는 hunk만 추리되, 바뀌는 줄은 빠짐없이 넣는다.

### 예시

- 리소스 변경 전 확인 → AskUserQuestion으로 "생성 / 취소" 선택지 제공
- 여러 구현 방안 중 선택 → AskUserQuestion으로 옵션 목록 제공
- 커밋 전 확인 → AskUserQuestion으로 "커밋 / 수정 / 취소" 선택지 제공
